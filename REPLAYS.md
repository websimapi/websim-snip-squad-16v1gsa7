# Live title feed and instant replays

- Title visitors subscribe to `watch-attract` without joining a lobby or occupying a seat. The server selects a random active round, resynchronizes geometry when switching, and rotates its selection every 45 seconds. Controls never reach the watched round.
- With no active round, `/api/replays/random` chooses from the latest 32 completed runs. The title passes the saved JSON to the Remotion Player composition in `replay-player.jsx`. Until a real run has been completed, it honestly displays an idle garden.
- `beginRecording` attaches to each authoritative 60 Hz physics step, not the 20 Hz network snapshots. Every frame records all character and seed transforms, velocities, alive/grounded state, shape revision, gameplay state, and scene animation values. Shape geometry is stored once per revision. Cut/reform events retain their exact physics-frame index and deterministic particle seed. Static asset placement is specified by a versioned scene manifest and landscape seed; cloud, celestial, foliage, limb and particle animation is deterministic.
- In-progress and abandoned runs live only in memory. On a server-confirmed goal, JSON is split into sub-64 KB chunks in `replay_chunks`. Metadata and the geometry/event manifest are published in `replays` only after all chunks have been written. A three-second completion bloom is included.
- Replays do not re-run physics. `replayState` can address any saved frame directly, and the shared renderer has a manual clock and deterministic effect reconstruction for Remotion. There is no MP4 rendering service or video-file storage.
- `node tests/replays.mjs` checks capture, geometry/events, completed-only persistence, JSON endpoints and seatless live observers. `REPLAY_FIXTURE=/tmp/replay.json node tests/replays.mjs` optionally writes a local test fixture; fixtures are never inserted into the real replay library.
